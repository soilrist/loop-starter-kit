description: 사람이 한마디로 게임이나 큰 기능을 만들라고 할 때 사용("이런 게임 만들어", "~같은 거 만들고 싶어", "이거 만들어!", "새 기능: ~"). 한마디를 설계서·질문 묶음·로드맵으로 바꾸고 루프가 바로 일할 수 있게 준비한다.
---

목표: 사람이 한 번만 대답하면 루프가 몇 시간 혼자 일할 수 있는 상태를 만든다.

1. `docs/conventions/Autonomy.md` 를 읽는다. (무엇을 혼자 정하고 무엇을 묻는지)
2. **있는 것부터 읽기** — 프로젝트에 이미 기획 문서·코드·에셋·README 가 있으면 먼저 훑어서(grep·목록) 그걸 출발점으로 삼는다. 이미 정해진 건 다시 묻지 않는다.
3. **이해하기** — 한마디에서 뽑는다: 장르·레퍼런스·느낌·플랫폼·규모. 레퍼런스 게임이 있으면 웹에서 핵심 시스템을 조사해 "같은 느낌, 다른 게임"이 되게 차이점을 잡는다. (베끼지 않는다)
4. **설계서 초안** — `docs/DESIGN.md` 틀을 채운다.
   - 🟢 초록은 채운다.
   - 🟡 노랑은 무난한 해석으로 채우고 `〔가정: …〕` 표시.
   - 🔴 빨강 중 방향은 비워 두고 질문 목록에, 숫자는 전부 `-1` 로 두고 6장 표에.
5. **질문 묶음 1회** — 사람에게 한 번에 보낸다. 최대 5개, 각각 선택지 2~4개 + 추천 + "고르면 무엇이 달라지나" 한 줄. 숫자 표는 따로 "나중에 채워도 되는 숫자"로 붙인다. **질문 앞에 "지금 가정한 것" 3~5줄 요약**을 보여 줘서 틀린 가정을 사람이 바로 잡게 한다.
6. 답을 받으면 DESIGN 에 반영하고 `〔가정〕` 을 확정/수정한다. 결정은 `docs/decisions/` 에 한 장씩.
7. **로드맵** — `docs/ROADMAP.md` 를 M0(뼈대)~Mn 으로 쪼갠다. 조각마다 ID(`M1-03`)와 합격 기준 한 줄. 조각 하나 = 커밋 하나 크기(10분 안팎). 첫 마일스톤은 "화면에서 뭔가 움직인다"가 빨리 나오게.
8. 복잡한 조각은 `docs/templates/FeatureSpec.md` 로 명세를 `docs/specs/` 에 만든다 (M0·M1 것만. 뒤는 루프가 그때 만든다).
9. `docs/STATUS.md` "지금 상태"를 채우고, INBOX 에 남은 `질문`·`확인` 을 정리한다.
10. 사람에게 보고: "설계서·로드맵 준비됨 / 루프가 먼저 할 조각 3개 / 아직 답 필요한 것" — 5줄 이내. 루프 켜기(`loop/ctl.sh on`)는 사람이 "켜"라고 할 때 감독이 한다.

커밋은 `docs(design): 킥오프 초안`, `docs(roadmap): M0~M3 조각 나누기` 처럼 나눠서, 사람 확인 후.
이 파일과 규칙 문서 내용이 다르면 규칙 문서를 따른다.
