description: 무언가를 만들거나 고쳐 달라는 요청인데 더 좁은 스킬이 없을 때 사용 (기능·화면·스크립트·영상 한 단계·자동화 한 단계·보고서 한 부분 — 종류 무관). 합격 기준 → 확인 방법 → 작은 조각 → 검사 인용 순서로 끝낸다. 게임 스크립트·콘텐츠·보이는 것은 new-script / new-content / new-visual 이 먼저다.
---

1. **프로필 하나만 읽는다** — `CLAUDE.md` 의 `프로필:` (조각 줄에 `〔프로필: …〕` 가 있으면 그것). `docs/profiles/<프로필>.md` 의 "안 쓰는 것" 은 열지 않는다.
2. **끝난 모습 한 줄** — 합격 기준을 눈으로·명령으로 확인되는 문장으로. ROADMAP·INBOX 줄에 이미 있으면 그대로 쓴다. 없으면 적고 시작한다.
3. **확인 방법을 먼저 정한다** — 프로필의 검사 3층에서 이 조각에 쓸 명령·캡처를 고른다. 프로젝트 검사 명령은 `docs/STATUS.md` "검사 명령" 칸. 칸이 비었으면 찾아서(`package.json` scripts, `Makefile`, `pyproject.toml` 등) **채워 넣는다** — 다음 바퀴가 다시 찾지 않게.
4. **있는 것부터 찾는다** — 비슷한 것이 이미 있는지 `grep`. 있으면 새로 만들지 않고 고친다.
5. **신호등** — `conventions/Autonomy.md` + 프로필의 🔴. 🔴 에 닿으면 **직전까지** 만들고 `[!] 사람:` 으로 넘긴다. 돌아가는 길을 찾지 않는다.
6. **조각 하나만** — 10분 안팎, 커밋 하나. 크면 자르고 나머지는 ROADMAP 에 줄로 적는다. 숫자는 `docs/DESIGN.md` §6 에서 가져오고, 없으면 근거와 함께 먼저 적는다.
7. **검사** — 1층 → 2층 → 3층. 명령 출력의 결과 줄을 인용한다 (`conventions/Verification.md`). 인용 못 하면 "못 함 — 이유" 로 적는다. "됐을 것" 은 없다.
8. **막히면** — 같은 실패 두 번이면 스킬 `unblock`.
9. **기록** — 감독·수동이면 한 것 / 문제 / 사람이 정할 것 세 줄. 루프 일꾼이면 `loop/PROMPT.md` ⑤⑥ 대로.

이 파일과 규칙 문서 내용이 다르면 규칙 문서를 따른다.
