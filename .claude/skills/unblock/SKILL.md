---
name: unblock
description: 막혔을 때 사용 — 같은 실패가 두 번 났을 때, 도구·명령·권한이 없을 때, 에러 원인을 모를 때, "안 돼"·"왜 안 되지"·"막혔어" 라는 말을 들었을 때. 사다리 여섯 칸을 내려가며 반드시 길을 내거나, 해 본 것을 적어 넘기고 다음 일로 간다. 그냥 멈추지 않는다.
---

`docs/conventions/Routing.md` §2 사다리를 그대로 탄다. 한 칸에서 두 번 실패하면 다음 칸. 같은 걸 세 번 하지 않는다.

0. **먼저 가른다** — 🔴(`Autonomy.md` + 프로필의 🔴)에 닿아서 막힌 거면 사다리가 아니다. 6번으로 바로 간다.
1. **읽기** — 에러 글을 끝까지 읽는다 (`tail -n 40`). 글 그대로 `grep` 으로 저장소·`logs/`·`docs/bugs/`·`CLAUDE.md` 함정에서 찾는다. 전에 고친 적 있으면 그 방법.
2. **좁히기** — 가장 작은 재현 하나를 만든다. `git log -5 --oneline`, `git diff` 로 마지막으로 되던 때와 다른 점을 본다. 가설을 한 줄 적고 그것만 확인한다.
3. **다른 도구** — 같은 목적의 다른 길. 없는 명령은 있는 것으로 (`python3`→`python`, `timeout`→`run_with_timeout`, MCP 죽음→CLI·파일 직접). 환경을 고치기 전에 돌아가는 길부터.
4. **찾기** — 공식 문서·검색 (도구가 있을 때). 쓰는 버전을 먼저 확인하고 그 버전으로 찾는다.
5. **돌아가기** — 목표는 그대로, 방법을 바꾼다: 조각을 더 작게 다시 자르기 / 가짜(목)로 먼저 잇고 진짜는 다음 조각 / 다른 접근으로 같은 합격 기준.
6. **넘기기** — 이 조각 줄을 `[!]` 로 바꾸고 세 가지를 적는다: **해 본 것 · 남은 가설 · 다음 사람이 볼 곳(파일:줄, 로그)**. 사람만 풀 수 있으면 `[!] 사람: <할 일>`. 그리고 **다음 조각으로 간다**.

풀렸으면:
- 커밋 본문이나 `docs/bugs/` 에 세 줄 — 증상 / 원인 / 고친 것.
- 같은 막힘이 두 번째면 `CLAUDE.md` 함정(또는 프로필 "이 종류의 함정")에 한 줄.
- 감독·수동이면 한 줄로 보고: 무엇이 막혔고 몇 번 칸에서 풀렸는지.

하지 않는 것: 검사를 끄거나(`--no-verify`) 테스트를 지워서 통과시키기, 에러를 삼키는 try/catch 로 덮기, 🔴 를 돌아가기.
