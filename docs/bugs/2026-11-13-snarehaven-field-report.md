# 현장 보고 — Snarehaven (키트 v2.5/2.6, 2026-11-11~13)

감독이 직접 겪은 것. 제안은 맨 아래.

## 겪은 일
1. **INBOX 32KB(한도 12,000자)까지 방치.** 경고는 `alerts.log` 한 줄뿐이라 감독이 하루 넘게 못 봄. 그동안 루프가 헛바퀴 3번 → 쉬는 시간 3600초로 늘림(11-11 01:21·08:46·14:18·19:51 반복). 감독이 직접 옛 항목을 `INBOX_ARCHIVE.md` 로 덜어냄.
2. **`ctl.sh tidy` 는 루프가 도는 중이면 거부** → `wrapup` 후 바퀴가 끝나길 기다렸다 tidy → `on` 해야 함. 감독 몫 3단계를 손으로 이어야 함.
3. **루프가 `질문` 을 INBOX 에 올린 뒤 「할 일 없음 — STOP」 을 6바퀴(#2733~#2738) 연속 만들며 멈춤.** 감독이 보고를 안 보면 몇 시간 정지. 질문 답을 기다리는 것과 진짜 할 일 없음을 구분 못 함.
4. **`ctl.sh on` 이 `core.hooksPath` 미설정이면 「훅 미설치」로 실패** — 새 checkout·worktree 마다 재발.
5. **봇 로그 파일명이 날짜뿐(`autoplay_YYYYMMDD.log`)** — 어제 런 로그를 오늘 것으로 읽고 이미 고친 결함을 원인으로 진단함(감독 오분석 1회).
6. 감독이 고친 INBOX 가 루프 몫 항목을 지워 버린 것처럼 보이는 일(줄 번호로 자르다 항목 소실) — 보관은 항목 단위 이동이 안전.

## 제안
- `loop.sh` 가 INBOX/STATUS 한도 초과 시 `alerts.log` 대신 **감독이 보는 곳(STATUS 맨 위 한 줄·알림)** 에 올리고, 초과 2바퀴면 INBOX 도 `tidy` 가 보관하게.
- `ctl.sh tidy --when-idle`: wrapup → 바퀴 종료 대기 → tidy → 커밋 → on 을 한 번에.
- 「할 일 없음」 판정 전에 INBOX 에 감독 답을 기다리는 `질문` 이 있으면 STOP 대신 **대기 상태 + 경고** 로 두고 `질문 대기 N시간` 을 보고.
- `ctl.sh on` 이 훅 경로를 스스로 설정(또는 설정 명령을 안내가 아닌 자동 실행).
- 봇·검사 로그는 시작 시각을 파일명에 넣도록 키트 예시 반영.
