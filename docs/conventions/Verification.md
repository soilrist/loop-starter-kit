# 검사 규칙

## 한 줄 요약
**"캡처는 검사다, 증거가 아니다."** 찍는 목적은 "했다"를 남기는 게 아니라 **틀린 걸 찾는 것.** 찾으면 그 바퀴 안에서 고치고 다시 찍는다.

## 검사 3층 (아래부터 순서대로, 아래가 실패하면 위로 안 올라감)
| 층 | 무엇 | 도구 | 실패하면 |
|---|---|---|---|
| 1. 기계 검사 | 컴파일, 이름·폴더 규칙, 자리표시, 중복 ID | 콘솔, `tools/check_conventions.py`, EditMode 테스트 | 커밋 금지 |
| 2. 동작 검사 | 실제로 눌러서 돌아가나 | PlayMode 테스트, **실제 입력 경로 주입** | 커밋은 가능, 같은 바퀴에 fix |
| 3. 눈 검사 | 화면이 이상하지 않나 | 캡처 + 체크리스트 | 같은 바퀴에 fix, 못 고치면 INBOX `막힘` |

엔진별 구체 방법은 `docs/checks/<엔진>.md` — Unity `docs/checks/unity.md`, Unreal `docs/checks/unreal.md`, Godot `docs/checks/godot.md`.

## 규칙
1. **못 한 검사는 "통과"가 아니라 "못 함"으로 적는다.** STATUS 에 `검사: 1층 통과 / 2층 통과 / 3층 못 함(에디터 꺼짐)`. 왜: 거짓 통과 한 번이 이후 모든 바퀴를 속인다.
2. **UI 는 코드 호출이 아니라 실제 입력으로 검사.** `button.onClick.Invoke()` X → 포인터 이벤트 주입/Input System 테스트로 클릭. 왜: 코드로 부르면 버튼이 다른 창에 가려져 있어도 통과한다.
3. **자리표시 검출은 눈이 아니라 코드로.** `-1`, `TBD`, `Lorem`, `New Text`, 분홍색(누락 셰이더), 흰 네모(누락 스프라이트)는 검사기가 찾는다.
4. **같은 지적 두 번 → 규칙으로 올리고 → 검사로 만든다.** 순서: `docs/postmortems/` 에 기록 → 해당 컨벤션 문서에 규칙 추가 → `check_conventions.py` 나 테스트에 검사 추가. 왜: 규칙만 쓰면 다음 AI가 또 어긴다. 검사는 못 어긴다.
5. 사람이 Play 중이거나 실기 테스트 중이면 루프는 코드·에셋 변경 금지 (INBOX 맨 위 `보류:`).
6. **테스트는 미정 숫자(`-1`)에 기대지 않는다.** 테스트 안에서 **테스트 전용 값**을 넣은 데이터를 만들어 쓴다 (Unity `ScriptableObject.CreateInstance`, Unreal `NewObject<UDataAsset>`, Godot `.new()` — 테스트 값은 게임 밸런스가 아니라서 🟢). 실제 데이터로만 볼 수 있는 3층 캡처가 미정 숫자에 막히면 `못 함(미정 숫자)` 으로 적는다.
7. 런타임 코드는 `-1` 을 만나면 에러 로그(`[Data] 미정 숫자: <에셋>.<필드>` — Unity `Debug.LogError`, Unreal `UE_LOG(..., Error, ...)`, Godot `push_error`)를 찍고 안전한 동작(이동 0, 무적 등)을 한다. 왜: 미정 숫자가 조용히 이상한 게임을 만들지 않게.

## 캡처 눈 검사 체크리스트 (3층)
- [ ] 분홍색 / 검정 네모 / 흰 네모 없음 (누락 재질·스프라이트)
- [ ] 글자 잘림·겹침 없음, 한글 깨짐(□□) 없음
- [ ] 자리표시 글자 없음 (`New Text`, `TBD`, 키 이름 그대로 `ui.btn.ok`)
- [ ] 캐릭터 발이 땅에 붙어 있음, 정렬 순서(앞뒤) 맞음
- [ ] 픽셀아트면 흐림(필터링) 없음, 크기 배율이 정수
- [ ] 이번 조각의 합격 기준 문장이 화면에서 보임
- 캡처 파일: `captures/<바퀴번호>_<범위>_<설명>.png` — 합격 캡처만 커밋, 나머지는 `captures/tmp/`
