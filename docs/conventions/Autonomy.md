# 자율 판단 규칙: 언제 혼자 정하고, 언제 묻나

## 한 줄 요약
**사람은 "무엇을·어떤 느낌으로·얼마나"만 정한다. "어떻게"는 AI가 정하고 기록한다.**

비유: 유능한 비서는 "회의실 어디 잡을까요?"를 묻지 않고 알아서 잡은 뒤 적어 둔다.
대신 **"예산 얼마까지 써요?"** 와 **"이 사람이랑 계약해요?"** 는 꼭 묻는다.

## 신호등 3색

### 🟢 초록: 혼자 정하고 바로 진행 (묻지 않는다)
되돌리기 쉽고, 플레이어가 느끼는 게임이 바뀌지 않는 것.
- 코드 구조, 클래스 나누기, 알고리즘, 사용할 Unity 기능
- 파일·폴더 위치, 이름 (컨벤션 문서대로)
- 조각 순서, 조각 크기, 테스트 방법
- 임시 그래픽(네모·원·단색 자리표시), 임시 효과음
- 패키지 선택 중 **무료·Unity 공식** 패키지
- 버그 고치는 방법

→ 크게 방향이 갈리는 것만 `docs/decisions/` 에 결정 기록 한 장. 작은 건 커밋 본문 "왜" 한 줄로 충분.

### 🟡 노랑: 가정하고 진행 + INBOX 에 `확인` (막히지 않는다)
플레이 느낌에 영향이 있지만, 나중에 바꾸기 쉬운 것.
- 설계서가 애매한 부분의 해석 ("적이 플레이어를 보면 쫓아온다" → 시야 거리는? 방식은?)
- UI 배치, 연출 순서, 조작 키 배치
- 설계서에 없는 작은 기능이 꼭 필요할 때 (일시정지 메뉴 같은)

→ 가장 무난한 해석으로 만들고, INBOX 에 `확인:` 을 남긴다. **사람이 답 안 해도 계속 진행.**
→ 설계서 해당 절에 `〔가정: …〕` 표시를 남겨서 나중에 한눈에 찾게.

### 🔴 빨강: 반드시 묻는다 (그 부분만 멈추고 다른 조각으로)
1. **숫자** — 체력·공격력·속도·확률·가격·경험치 곡선. `-1` 자리표시로 두고 `질문:`. **추천 숫자도 쓰지 않는다.** (테스트 코드 안에서만 쓰는 테스트용 값은 예외 — Verification.md)
2. **되돌리기 비싼 방향** — 장르, 시점, 아트 스타일, 타깃, 핵심 재미(필러), 조작 방식의 뼈대, 플랫폼
3. **돈·계정·밖으로 나가는 것** — 유료 에셋·서비스, 새 계정, 스토어 업로드, 외부 공개, 개인정보
4. **지우는 것** — 사람이 만든 파일·에셋 삭제, 이미 합친(main) 기능 제거
5. **권리** — 상업 이용이 확인 안 된 에셋·모델, 실존 인물·브랜드·다른 게임을 그대로 베끼는 것
6. **규칙 자체를 바꾸는 것** — 컨벤션 문서·검사기·훅·PROMPT 수정. 루프는 `질문`으로 제안만, 반영은 사람 승인 후 **감독**이.

## 묻는 방법 (사람 시간을 아끼는 법)
1. **모아서 한 번에.** 질문이 생길 때마다 하나씩 보내지 않는다. 감독이 모아서 보고 때 한꺼번에.
2. **고르기 쉽게.** 방향 질문은 선택지 2~4개 + 각 선택지의 결과 한 줄 + (숫자가 아니면) `추천`.
3. **숫자는 표로.** `이름 / 단위 / 설계서 근거 / 비교 대상(있으면)` — 값 칸은 비워 둔다.
4. **답이 없어도 멈추지 않는다.** 빨강 항목이 걸린 조각은 건너뛰고 다른 조각을 한다. 할 조각이 전부 빨강에 막혔을 때만 STATUS 에 "막힘" 기록 후 스스로 멈춘다 (감독이 사람에게 묻고 다시 켬).
5. 사람이 **"알아서 해"** 라고 답하면: 방향 질문은 `추천` 채택 + 결정 기록. **숫자는 예외 — "알아서 해"여도 묻는다.** (단, 사람이 "임시값 넣어도 돼"라고 명시하면 `〔임시〕` 표시와 함께 넣고 INBOX 에 남긴다)

## 스스로 점검 (판단 전 3초 질문)
- 이걸 **플레이어가 느끼나?** 아니면 🟢
- 느끼는데 **내일 바꾸기 쉽나?** 쉬우면 🟡
- **숫자·돈·지우기·방향·권리·규칙** 중 하나면 🔴

## 사람이 한마디만 했을 때 ("〔이런 게임〕 만들어")
`kickoff` 스킬을 쓴다. 한마디를 → 설계서 초안 → 빨강 질문 묶음 → 로드맵 → 루프 시작까지 이어 준다.
