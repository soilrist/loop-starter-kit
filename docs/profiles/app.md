# 프로필: app

**언제** — 결과물이 실행되는 코드일 때: 웹·모바일 앱·서버·API·CLI·라이브러리.

**결과물** — 돌아가는 기능. 조각 하나 = 쓰는 사람이 할 수 있게 된 일 하나 (화면 하나·엔드포인트 하나·명령 하나).

**검사 3층**
| 층 | 여기서 뜻하는 것 |
|---|---|
| 1 기계 | 빌드·타입 검사·린트 0 에러 (`STATUS.md` 의 "검사 명령" 칸에 적힌 명령 그대로) |
| 2 동작 | 테스트 통과 + **실제로 띄워서** 한 번 지나가기 (서버면 요청, 화면이면 브라우저, CLI 면 실행) |
| 3 눈 | 화면 캡처·응답 본문·출력을 직접 읽고 아래 다섯 칸 |

**쓰는 사람 눈 다섯 칸** (처음 쓰는 사람이라 치고)
1. 뭘 해야 하는지 설명 없이 아는가
2. 누르면·보내면 바로 반응하는가 (기다림엔 표시가 있는가)
3. 틀렸을 때 뭐가 틀렸고 어떻게 고치는지 알려 주는가
4. 빈 상태·긴 글자·느린 망·작은 화면에서 깨지지 않는가
5. 다시 들어왔을 때 하던 것이 남아 있는가

**이 종류의 🔴** — 운영 배포·운영 DB 스키마 바꾸기·데이터 지우기·결제·실제 사용자에게 가는 메일/알림·비밀 값 건드리기·공개 API 를 호환 안 되게 바꾸기.

**여는 문서·스킬**
- 스킬: `build-slice` (기능 조각), `unblock` (막혔을 때), `release`
- 설계서: `docs/DESIGN.md` — §5 는 화면·기능 목록, §6 은 한도·요금·시간 제한 같은 숫자
- 프로젝트 고유 검사 명령은 `docs/STATUS.md` "검사 명령" 칸에 한 번 적고 그것만 쓴다

**안 쓰는 것** — `docs/engines/`, `docs/checks/`, `conventions/Reference.md`·`AssetNaming.md`·`PlayerEye.md`, 스킬 `new-script`·`new-content`·`new-visual`·`reference-sheet`. 열지 않는다.

**이 종류의 함정**
- "테스트 통과" 는 2층의 절반이다. 띄워서 지나가지 않았으면 통과가 아니다.
- 로컬 통과 ≠ 배포본 통과. 배포는 🔴 이므로 감독·사람에게 넘긴다.
